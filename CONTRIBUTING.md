# Contributing to KaiOrc

Thanks for your interest in KaiOrc. It's early and pre-1.0, so the shape of things is still settling — please open an issue to discuss any non-trivial change before sending a pull request, to avoid spending effort on something that doesn't fit the direction.

## Reporting bugs

Open an issue using the bug report template. Include a minimal reproduction where possible.

## Proposing features

Open an issue using the feature request template first. KaiOrc is deliberately scoped (see the README's Non-Goals section) — features that fit a specific AI provider's quirks or a single framework's conventions are usually out of scope.

## Pull requests

1. Fork the repo and create a branch from `master`.
2. Keep changes focused — one logical change per PR.
3. Match the existing code style (no added comments unless they explain a non-obvious *why*).
4. Make sure the build passes (`./gradlew build`) before opening the PR.
5. Describe what changed and why in the PR description.

## Code of Conduct

This project follows the [Code of Conduct](CODE_OF_CONDUCT.md). Please read it before participating.
